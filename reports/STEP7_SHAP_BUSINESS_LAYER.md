# Step 7 — SHAP Explainability & Business Risk Layer

## Objective

Turn the LightGBM model into an analyst-friendly risk decision layer.

### Outputs

- `reports/shap_feature_importance.csv` — ranked model drivers
- `reports/figures/05_shap_feature_importance.png` — top 20 drivers
- `reports/risk_action_list.csv` — loan-level PD and expected loss ranking
- `reports/risk_threshold_analysis.csv` — manual-review threshold scenarios
- `reports/score_decile_business_summary.csv` — decile-level validation

## Expected Loss

The portfolio layer uses:

`Expected Loss = PD × LGD × EAD`

For this portfolio project, **LGD = 45% is an illustrative assumption**, not a company policy or observed LGD estimate.

EAD is approximated using `credit_amount` when available.

## How to run

From the project root:

```bash
python python/05_shap_business_layer.py
```

The script expects:

- `data/processed/loan_features.csv`
- `models/lightgbm_bundle.joblib`

Both are generated by earlier project steps.

## How to explain this in an interview

> "After training the LightGBM challenger model, I used SHAP to explain which features were driving individual predictions. I then translated probability of default into a business-oriented expected-loss view using PD, an illustrative LGD assumption, and exposure. Finally, I tested different risk thresholds to understand the trade-off between investigation workload and default capture."

## Important modeling note

The current model uses a stratified train/test split because the analytical table does not yet contain a reliably validated decision-date field for an out-of-time split. For production use, an out-of-time validation strategy should replace the random split once the correct application/decision date is established.
